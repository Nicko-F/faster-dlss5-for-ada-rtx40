# 技术报告：Ada 上的 DLSS5 推理加速

[English](optimizations.md)

## 1. 目标与系统边界

Faster DLSS5 是基于 [RenoDX DLSS5](https://github.com/RankFTW/rhi-repo) 的
Ada / RTX 40 加速补丁。优化目标是神经渲染执行：保留模型数值运算、MMA 累加顺序与
数据依赖，调整数据搬运、寄存器活跃区间及调度方式，使其更适合 Ada。

社区 base 负责游戏接入、NR 运行库、模型参数、图像分区和 padding。
我们的适配层在原有网络调用位置选择优化函数，沿用原始资源绑定、参数缓冲区和启动描述符。
因此，即使一个算子已经高度融合，也可以在保持外部契约的同时改变内部数据的暂存与消费方式。

选定组合覆盖 encoder、ViT、decoder 和时序 Pre/Post。
一轮时序网络可替换 **145 次内部调用和 2 次 Pre/Post 调用**。
包中包含 **45 个内部二进制变体和 2 个表面内核**：调用次数与二进制数量不同，
因为多个调用会复用同一个二进制，部分尺寸也会选择专用变体。

## 2. 成本模型：为什么能运行仍可能不够快

用于定位瓶颈的近似模型是：

`T内核 ≈ max(T张量计算, T搬运) + T未被隐藏的依赖等待 + Tspill + T指令发射`

这些项不是互相独立的可加计数器。复制、计算和访存服务可以重叠，改变一个 tile
可能同时影响多项成本。因此，我们结合编译资源信息和运行测量判断方案，
不会只按指令数量给候选排序。

NVIDIA 的 Ada 调优指南给出，计算能力 8.9 的每个 SM 可驻留 48 个 warp，
拥有 64K 个 32 位寄存器和 100 KB shared memory。
寄存器或 shared memory 分配可能先于算术吞吐限制活跃 CTA 数量。
[NVIDIA Ada 调优指南](https://docs.nvidia.com/cuda/ada-tuning-guide/index.html)

对于每 CTA 有 `B` 个线程、每线程约分配 `R` 个寄存器的情况，
`floor(65536 / (B × R))` 可以作为寄存器容量约束下 CTA 数量的初步上界。
实际还受分配粒度、warp/block 上限与 shared memory 限制。
所以，提高寄存器数量虽然可能减少 spill，也可能减少可用于隐藏延迟的 warp。
本文有关 occupancy 的解释来自容量模型与编译信息，并非直接测量 D3D 命令列表的驻留情况。

## 3. 异步复制与完成时机

将 bulk transfer 适配为较小的逐线程复制时，如果每组复制后立刻等待，
虽然用了异步指令，关键执行路径仍可能接近串行。

我们保留生产者与消费者的数据依赖，将完成等待放到真正消费数据的边界。
保留的实验使用每 lane 16 字节异步复制及完成计数，允许在发出复制与使用目标数据之间
执行独立算术。暂存区复用仍需等待此前读者和未完成写入结束。

概念调度如下：

```text
发出下一块 tile 的搬运
计算已经就绪的 tile
消费下一块 tile 前，确认对应搬运组完成
此前读者结束后，再复用暂存区
```

CUDA 的异步复制与 barrier 机制区分“发出工作”和“建立完成依赖”。
[CUDA 编程指南](https://docs.nvidia.com/cuda/cuda-programming-guide/index.html)

等待位置、暂存生命周期和最终寄存器分配需要一起评估。
早期包含 12 个入口的异步/资源组合，在交替和独立进程测量中带来了约
**2.93–3.55% 的完整 NR 降耗时**。这是组合结果，不能把全部收益归因于异步复制。
保留原生复制的对照接近零收益。

## 4. 寄存器压力、uniform lowering 与 local spill

核心指标是同一时刻存活的值有多少。
过早加载的输入片段可能跨越地址构造、同步和其他矩阵运算一直占用寄存器。
将不可变数据的加载移近使用位置，可以缩短这些活跃区间，同时保持算术顺序。

寄存器优化结合三种选择：

1. 将片段加载移近消费者。
2. 在能减少重复装载的位置，保留跨 MMA 的有效复用。
3. 在完整融合内核中对比寄存器上限和编译器分配结果。

一组 512 通道输入/输出投影审计显示：等待式适配使用 **80 字节 stack**，
初次异步改写使用 **88 字节**，进一步调整后为 **0 字节**。
改进样本分别使用 **126 / 123 个寄存器**，shared memory 都是 **12,312 字节**；
检查到的 local load/store 指令消失。这是具体投影样本的资源结果。

Uniform lowering 是问题的一部分，但需要准确描述。
审计发现 **24 个入口中 132 处 uniform FP8 零值转换**在 Ada 路径中改变了表示方式；
将 uniform 指令纳入后，总转换数量仍然一致。
Ada 也有 uniform-register 设施。证据指向 lowering 差异和普通寄存器压力，
不能解释成 RTX 40 没有 uniform register，也不能直接推导出 32 倍开销。

最终目标是降低执行耗时。寄存器上限、加载位置与数据复用需要组合选择，
在 spill 流量和活跃 warp 容量之间取得合适的平衡。

## 5. 融合 FFN、投影及边界调度

融合内核包含多个内部计算阶段。优化其中一段不必改变其 API 边界。
我们围绕输入片段复用、加载位置和资源分配工作，保留数值操作顺序以及下一阶段期待的内存布局。

在部分 256 通道边界中，较宽的输出分组允许一个输入片段在重新加载前服务更多计算。
这用更大的活跃集合换取更少的输入流量。部分位置也保留了延后 shared-memory 加载、
简化寄存器分配等措施；更复杂的 tiling 并不总能胜过这些改动。

较大的局部收益集中在网络深层：

| 测量组 | 局部调用回放耗时合计下降 | 测量口径 |
|---|---:|---|
| 512 FFN，15 次调用 | 39.11% / 39.74% | 相对社区，两种顺序 |
| 512 pooling | 16.29% / 16.45% | 同轮局部测试 |
| 完整 512 组，66 次调用 | 22.31% / 22.18% | 局部调用中位数求和 |
| ViT 计算，40 次调用 | 12.29% / 12.40% | 模块测试 |
| 选定的 256 边界 | 19.02% / 18.89% | 边界测试 |

这些组存在重叠，各轮也有自己的对照组合，不能相加成为最终 NR 收益。
Hot replay 会反复使用同一算子和资源；完整推理还包含相邻计算、依赖关系和缓存驻留变化。

128/64/32 等较小阶段，每单位调度和暂存开销对应的计算更少，
因此需要结合通道数与尺寸选择执行组织。

## 6. Shared memory：选择值得迁移的访问

Local spill 由设备内存支持，但访问可能命中缓存。
迁移到 shared memory 会改变访问路径，同时增加片上容量、寻址、bank 布局及潜在同步成本。
单看空闲容量无法判断哪条路径更快。

Shared-memory 收敛最终保留三个小范围类别、共十次调用：

| 保留类别 | 相对已优化组合的局部追加降耗时 | 解释 |
|---|---:|---|
| 8 次 attention | 1.12–1.25% | 选定的 shared-memory / 资源组织调整 |
| 512 pooling | 2.05–2.42% | 固定 block 代码生成；pragma 开关二进制完全一致 |
| 256 downsampling | 0.52–0.83% | 小幅可重复局部收益 |

Pooling 的控制实验将机制定位为固定 block 代码生成。
Shared-memory 改动结合周围的寄存器与同步成本，以实际执行收益决定保留范围。

## 7. 时序 Pre/Post 与尺寸处理

Pre/Post 处理内部网络前后的表面输入输出。
选定的 Pre 保留原纹理访问调度，采用 128 寄存器上限及 local spilling，
时序帧局部重复测试下降 **6.60–9.82%**。
选定的 Post 使用 128 寄存器上限及 shared spilling，局部下降 **2.84–4.19%**。
没有历史的初始化路径等不符合所选时序契约的情况，沿用原生函数。

适配层读取原生尺寸和 padding。此前四处尺寸常量折叠位置加入了通用变体，
遇到已知精确尺寸时仍可选择更快的特化路径。玩家不需要选择分辨率配置。
[尺寸设计及验证矩阵](dynamic-dimensions.zh-CN.md)。

## 8. 运行时集成与兼容性

玩家只需在社区插件旁安装一份内核包。适配层相对自身位置定位它，
正常启动游戏即可加载，无需自定义启动环境。
接入通过 ReShade addon API、已加载的 NR/NVAPI 入口协商完成。
安装器不按游戏名、精确显卡型号、驱动字符串或社区 base 整文件哈希设置白名单。

开始替换前，完整原生执行会核对完整网络序列，以及每个候选替换位置的参数布局、尺寸关系、启动几何和资源契约。
无历史初始化图先走原生，后续符合要求的时序图完成核对后，再启用替换。
每次实际调用继续检查其当前契约；不匹配的调用沿用社区函数。

接口与调用契约匹配可以支持兼容的打包或插件更新，但不能证明一个在相同接口下
改变数学运算的未知模型仍然等价。这是兼容研究有意义的技术边界。
包校验用于完整性和实验溯源，不是上游版本白名单。

Evaluate 转发通过尾跳保留原始返回地址，构建时检查生成汇编。
这是因为普通包装调用曾破坏游戏接入。补丁改变的是函数选择，不是社区插件的呈现流水。

## 9. 验证与最终实测结果

验证从编译资源检查、算子回放逐步推进到输出对比、完整推理和游戏测量。
内部组合曾对 **200 个捕获张量/输出、共 2.171 GB 数据**完成一致性对比。
表面内核另做验证；跨尺寸矩阵使用独立原生/优化进程，对静态、运动及 NR+SR 输入的最终图像进行比较：12 组对照，
每个进程三帧，共 72 帧，最终图像逐字节一致。

| 分辨率 | 社区 NR → 优化 NR | NR 降耗时 | 游戏社区 → 优化 FPS |
|---|---:|---:|---:|
| 1920×1080 | 4.7539 → 4.4994 ms | 5.35% | 91.37 → 92.62 |
| 2560×1440 | 7.5083 → 6.8246 ms | 9.11% | 66.77 → 69.50 |
| 3840×2160 | 17.6821 → 15.8614 ms | 10.30% | 31.08 → 32.38 |

上表 NR 采用交替对照。4K 独立进程结果为 **18.2810 → 16.7892 ms，下降 8.16%**。
测试显卡 RTX 4080，驱动 616.56；游戏数据来自《赛博朋克 2077》benchmark。
计时样本在固定形状构建中测量选定优化。当前安装和契约检查改动有独立正确性记录，
不将这些验证转写为新的计时样本。

Amdahl 定律解释了整体收益的稀释：若某区域占基准耗时比例 `f`，
其自身耗时下降比例 `r`，忽略重叠与竞争变化时，整体下降约为 `f × r`。
占总耗时 25% 的区域加快到耗时下降 20%，整体理想下降是 5%。
不同基准、互相重叠区域的局部百分比也不能直接相加。

游戏新增成本按 `1000/FPS开启 − 1000/FPS关闭` 估算，包含接入及其与渲染的交互。
4K 测得 **16.714 → 15.416 ms**。公开 RTX 5070 Ti 的 **17 ms** 来自另一款游戏
《NBA 2K27》，作为背景参考，不能当成受控显卡速度比。
[测试方法与数据](benchmarks.zh-CN.md) ·
[TechSpot 参考](https://www.techspot.com/article/3170-real-dlss-5-performance/)。

## 10. 结果解读与后续方向

独立进程和交替测量都保留，因为缓存/历史、频率状态及运行顺序会影响小幅差值。
GPU 频率未锁定，交替分支共享历史状态；1080p 游戏提升较小且有波动。
最终图像一致性覆盖记录的输入，长期运动序列仍需要专门评估。

下一步优先改善暂存开销占比较大的低通道阶段，测量更多尺寸下的通用组合，
并验证契约兼容的社区更新。每项保留改动应具备明确局部机制、正确性结果及对照基准。

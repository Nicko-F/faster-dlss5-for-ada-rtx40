# 原生尺寸与自动调度

[English](dynamic-dimensions.md)

DLSS5 提供网络矩形、padding、tile 和启动参数。补丁沿用这些值，
为当前调用契约选择优化函数。一份安装随游戏的分辨率和宽高比工作。

多数选定内核本来就使用动态尺寸。四处存在尺寸折叠的位置具有通用变体；
遇到精确匹配的活动尺寸及内部尺寸时，可以自动选择相应特化路径。

## 正确性矩阵

| 输入 | 输出 | 验证内容 |
|---|---|---|
| 1600×1000、1920×1200、2560×1600 | 同尺寸 | 16:10 静态输入 |
| 3440×1440 | 同尺寸 | 超宽屏 |
| 1919×1199 | 同尺寸 | 奇数活动尺寸 |
| 1920×1080、2560×1440、3840×2160 | 同尺寸 | 常用静态输入 |
| 1920×1200、2560×1600、3440×1440 | 同尺寸 | 运动输入 |
| 1280×800 | 1920×1200 | NR + SR |

共 12 组独立社区/优化进程对照，每个进程运行三帧，共 72 帧。
每组最终导出图像逐字节一致。启动阶段用原生执行核对网络，随后通过契约的图
替换 145 次内部调用和 2 次时序表面调用，路由错误为零。
[机器可读记录](../benchmarks/dynamic-validation-2026-09-10.json)。

这些尺寸是测试样本，不是安装预设。通用调度依据运行库推导尺寸关系，
未列出的尺寸只要契约匹配，也可使用同一路径。
NR 输入尺寸与最终显示尺寸分别处理，NR + SR 对照覆盖了这种组合。

## 运行时接入

内核包包含 45 个内部变体和 2 个 Pre/Post 内核。
加速开始前，通过运行库入口、模型/格式信息和完整原生调用序列建立契约。
之后仍逐次检查当前形状和 ABI；契约变化时沿用社区函数。

证据采集于 RTX 4080 / 驱动 616.56，它们标识测试机器，不是安装限制。
更长时序、运行中切换分辨率和游戏动态分辨率属于后续测试目标。
本矩阵验证最终图像与路由，[性能测量](benchmarks.zh-CN.md) 使用各自记录的测试配置。
